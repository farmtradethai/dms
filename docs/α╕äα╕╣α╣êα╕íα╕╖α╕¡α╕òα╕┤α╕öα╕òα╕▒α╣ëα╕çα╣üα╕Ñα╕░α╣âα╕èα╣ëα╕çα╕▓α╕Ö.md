# คู่มือติดตั้ง ตั้งค่า และใช้งาน — Die Management System

## A. ติดตั้งบน Windows (เครื่องทดลอง / เครื่องในโรงงาน)

**ต้องมี**: Python 3.10 ขึ้นไป (python.org → ติ๊ก "Add Python to PATH" ตอนติดตั้ง) และอินเทอร์เน็ตครั้งแรกสำหรับโหลดแพ็กเกจ

1. แตก zip ไว้ที่ใดก็ได้ เช่น `D:\DieManagement\`
2. ดับเบิลคลิก **`run.bat`** — หน้าต่างดำจะทำ 3 ขั้น
   - `[1/3]` สร้างโฟลเดอร์ `.venv` (ครั้งแรกเท่านั้น)
   - `[2/3]` ติดตั้งแพ็กเกจ (ครั้งแรก 1-2 นาที)
   - `[3/3]` seed ข้อมูล: บริษัท AH/AHP/AHR, ทะเบียนแม่พิมพ์ 2,773 ตัว, ผู้ใช้จากรายชื่อจริง 53 คน, ประวัติ 2,919 งานจาก Power Apps — จนขึ้น **`DONE in xxs`**
3. เบราว์เซอร์เปิด http://localhost:8790 เอง → login **`ah_admin` / `1234`** (หน้า login มีปุ่ม "บัญชีทดลอง" คลิกแล้วกรอกให้)
4. **หน้าต่างดำต้องเปิดค้างไว้** ตลอดที่ใช้งาน (ปิด = เซิร์ฟเวอร์หยุด) · ครั้งถัดไปดับเบิลคลิก `run.bat` อีกครั้ง จะข้ามการติดตั้ง/seed เปิดได้ใน 5 วินาที
5. ให้คนอื่นในโรงงานใช้: เปิด firewall port 8790 แล้วเข้าที่ `http://<IP เครื่องนี้>:8790` จากมือถือ/คอม ใน Wi-Fi เดียวกัน

| ไฟล์ | ใช้เมื่อ |
|---|---|
| `run.bat` | เปิดใช้งานทุกครั้ง |
| `reset_data.bat` | ต้องการล้างข้อมูลทั้งหมดแล้วเริ่มใหม่ (ลบ `data/`) — **ไม่ต้องรันถ้าระบบใช้ได้อยู่** |
| `.env.example` | copy เป็น `.env` ถ้าจะเปลี่ยน port / รหัส admin / ต่อ Postgres |

ถ้า login ไม่ผ่าน: ดูบรรทัด `[login] FAILED user='...' (no such user / wrong password)` ในหน้าต่างดำ จะบอกสาเหตุทันที

## B. ตั้งค่าครั้งแรก (login ด้วย `ah_admin`)

เมนู **ผู้ดูแลระบบ** (ซ้ายล่าง) มีแถบ:

1. **ตั้งค่าบริษัท** — ชื่อบริษัท, ข้อความโลโก้, **Prefix เลขใบงาน** (AH ตั้งไว้ `AHMD` ต่อจาก 04995), **กะ & เวลาพัก** (ค่าเริ่มต้นตามโรงงานแล้ว), งาน PM ข้ามขั้น Foreman หรือไม่, URL/Key โปรแกรม Die Spare Part
2. **ผู้ใช้ & สิทธิ์** — รายชื่อช่าง/Foreman/QC จาก CSV ถูกสร้างแล้ว (รหัส `1234`) → ตั้ง username ที่จำง่าย, เปลี่ยนรหัส, กำหนด **กะ / Skills** ของช่าง (หัวหน้า Die จะเห็นตอนมอบหมาย) · เพิ่มพนักงาน Production ทีละคน
   - บทบาท: `production` แจ้งซ่อม+Try-out · `foreman` อนุมัติขั้น 1 · `die_leader` อนุมัติ+มอบหมาย · `technician` ซ่อม · `qc` ตัดสิน · `manager` ดูทุกอย่าง/แก้ไข · `admin` ตั้งค่าบริษัท
3. **Master data** — ปัญหา (Production เลือก), สาเหตุ (Die MT เลือก), Line, ลูกค้า · เครื่องมือ **Cleaning**: เปลี่ยน `LIne3`→`Line3` ทั้งระบบคลิกเดียว
4. **ช่องทางแจ้งเตือน** — เพิ่ม LINE / Telegram / Discord / Brevo email / Webhook เลือกเหตุการณ์ กด "บันทึก & ส่งทดสอบ"
   - LINE: สร้าง Messaging API channel ที่ developers.line.biz → Channel access token + ใส่ bot เข้ากลุ่ม → Group ID
   - Telegram: @BotFather สร้าง bot → token, ใส่ bot ในกลุ่ม → chat_id (ติดลบ)
   - Brevo: brevo.com ฟรี 300 ฉบับ/วัน → SMTP & API → API key, ยืนยันอีเมลผู้ส่ง
5. **นำเข้าข้อมูล** — ทำไปแล้วใน seed; ใช้อีกเมื่อมี CSV ใหม่จาก Power Apps (ข้ามเลขซ้ำอัตโนมัติ) หรือบริษัทอื่น · ปุ่ม **ปิดงานเก่าที่ค้าง** ปิด 591 งานเก่าที่ Production ไม่เคยกดรับใน Power Apps ให้ Dashboard สะท้อนความจริง (แนะนำให้กดหลังตรวจดูแล้ว)
6. **รูปภาพ/พื้นที่** และ **Backup** — ดูการใช้พื้นที่, Export ZIP, Archive รูปเก่า; สร้าง/ดาวน์โหลด backup ทุกสัปดาห์

## C. ใช้งานประจำวัน (ตาม flow เดิมของโรงงาน)

| ขั้น | ใคร | ทำอะไร | หน้าจอ |
|---|---|---|---|
| 1 | Production (`ah_prod`) | **แจ้งซ่อม / PM** → เลือก ลูกค้า→Model→Part→Process (หรือพิมพ์ค้นหา / สแกน QR แม่พิมพ์) → ปัญหา → Required day → ถ่ายรูป → ส่ง | เมนู "แจ้งซ่อม / PM" |
| 2 | Foreman/Eng (`ah_foreman`) | ได้แจ้งเตือน → เปิดใบงาน → **อนุมัติ** หรือ ไม่อนุมัติ (ต้องใส่เหตุผล) | "รออนุมัติ" |
| 3 | หัวหน้า Die (`ah_leader`) | เห็นภาระงานช่างแต่ละคน → ติ๊กช่าง 1-2 คน → **อนุมัติและมอบหมาย** | "รออนุมัติ" |
| 4 | ช่าง (`ah_tech1`) | **รับงาน/เริ่มซ่อม** (จับเวลา) → ถ่ายรูปก่อน → อัปเดต % → พัก/ทำต่อ → เพิ่มอะไหล่ที่ใช้ (สแกน QR ได้) → **ซ่อมเสร็จ** ระบุสาเหตุ+การแก้ไข+รูปหลัง | "งานของฉัน" |
| 5 | Production | ทดลองผลิต → **Try-out ผ่าน ส่ง QC** (กรอก downtime ได้) หรือ **ไม่ผ่าน ส่งกลับ** → วนกลับขั้น 3 | "รออนุมัติ" |
| 6 | QC (`ah_qc`) | **QC OK ปิดงาน** หรือ **QC NG ส่งกลับ** → วนกลับขั้น 3 จนกว่าจะผ่าน | "รออนุมัติ" |

- หน้าหลักของทุกคนแสดง "งานที่รอคุณ" ตามบทบาท + กระดิ่งแจ้งเตือน
- ใบงานทุกใบมี QR → พิมพ์ใบ Request (ปุ่ม พิมพ์/PDF) ติดไปกับแม่พิมพ์ สแกนด้วยมือถือเพื่อเปิด/อัปเดต
- แก้ข้อมูลผิด: ปุ่ม **แก้ไข** ในใบงาน (บันทึกว่าใครแก้อะไรใน Audit log)
- **แผน PM**: ทะเบียนแม่พิมพ์ → ตั้ง "รอบ PM (วัน)" + PM ล่าสุด → หน้าแผน PM แสดงเกินกำหนด/ถึงกำหนด → สร้างใบงาน PM (เดินตาม flow เดียวกัน) → QC OK แล้วระบบเลื่อนกำหนดถัดไปเอง
- **จอ TV**: เปิด `http://<IP>:8790/tv` บนทีวี login ด้วยบัญชี `ah_manager` กด F11 รีเฟรชเองทุก 30 วินาที
- **รายงาน**: เลือกช่วง/Line/ลูกค้า/ช่าง → Excel (7 ชีต) / CSV / PDF / ภาพ · **ตรวจข้อมูล**: งานค้างผิดปกติ, ข้อมูลที่ต้อง Cleaning, แม่พิมพ์ซ่อมซ้ำ, Line ที่ปัญหาพุ่ง

## E. เชื่อมโปรแกรม Die Spare Part Inventory
ตั้งค่าบริษัท › สร้าง **API Key** → ในโปรแกรมอะไหล่ใช้โค้ดจาก `scripts/spare_part_client_example.py`: เมื่อยืนยันใบเบิกโดยอ้าง DR No. ให้ `POST /api/v1/spare-issue` → ต้นทุนเข้าใบงานอัตโนมัติ; ส่งรายการต่ำกว่า Min ที่ `POST /api/v1/low-stock`; และเปิด endpoint `GET /api/parts/{code}` ฝั่งโปรแกรมอะไหล่ ให้หน้าสแกนของระบบนี้ดึงชื่อ/ราคาอะไหล่ได้ · ทดสอบ API ที่ `http://localhost:8790/api/docs`

## F. ล้างใบแจ้งซ่อม / ใบงาน PM เก่า เพื่อเริ่มใช้จริง (master ทั้งหมดอยู่ครบ)

login ด้วยบัญชี admin ของบริษัท (เช่น `ah_admin`) → **ผู้ดูแลระบบ › 🧹 ล้างใบงานเก่า**

1. **เลือกสิ่งที่จะลบ → กด "ตรวจนับ"** (ยังไม่ลบอะไร แค่นับให้ดู)
   - ขอบเขต: *เฉพาะใบงานที่นำเข้าจาก Power Apps* (มีเลข Legacy — ข้อมูลเก่าทั้งหมด 2,919 ใบ) / *ทั้งหมดของบริษัท* / *ตามช่วงวันที่*
   - ประเภท: ติ๊ก ซ่อมแม่พิมพ์ / PM / Die Accident — เช่น ลบเฉพาะ PM เก่า ให้ติ๊ก PM อย่างเดียว
   - สถานะ: ทุกสถานะ / เฉพาะที่ปิดแล้ว / เฉพาะที่ยังค้าง
2. ดูผลตรวจนับ: จำนวนใบงานที่จะลบ, ที่จะเหลือ, ช่วงวันที่, จำนวนรูป
3. ตัวเลือกเสริม (ไม่บังคับ):
   - ลบบัญชีช่างชั่วคราวที่ระบบสร้างตอนนำเข้า (ระงับอยู่ ไม่มีรหัสผ่าน)
   - ลบแม่พิมพ์ที่ไม่มี Die Code ที่สร้างอัตโนมัติจากข้อมูลเก่าและไม่มีใบงานเหลือ (ทะเบียนจริงที่มี Die Code ไม่ถูกแตะ)
   - ล้างวันที่ PM ล่าสุด/ถัดไป เพื่อเริ่มนับแผน PM ใหม่ (รอบ PM ที่ตั้งไว้ยังอยู่)
   - ล้างกระดิ่งแจ้งเตือนเก่า
   - **เลขใบงานถัดไป** เช่น ใส่ `1` → ใบงานใหม่เริ่ม `AHMD00001` (หรือเปลี่ยน Prefix/รูปแบบเป็น `DR-2610-001` ที่ ตั้งค่าบริษัท)
4. พิมพ์รหัสบริษัท (`AH`) เพื่อยืนยัน → กด **Backup แล้วลบ**

**สิ่งที่ถูกลบ**: ใบงาน + ประวัติสถานะ + ช่างที่มอบหมาย + เวลาทำงาน + อะไหล่ที่ผูก + รูปของใบงานเหล่านั้น — เฉพาะบริษัทที่เลือก
**สิ่งที่อยู่ครบ**: บริษัท · ผู้ใช้/รหัสผ่าน · ทะเบียนแม่พิมพ์ + รอบ PM · Master ปัญหา/สาเหตุ/Line/ลูกค้า · ตั้งค่า · ช่องทางแจ้งเตือน · API key · Audit log · ข้อมูลบริษัทอื่น

ความปลอดภัย:
- ระบบ **สร้าง Backup (รวมรูป) อัตโนมัติก่อนลบทุกครั้ง** ชื่อไฟล์แสดงหลังลบ — ลบผิด → หน้า Backup › กู้คืนไฟล์นั้น
- บันทึกใน Audit log ว่าใครลบอะไรเมื่อไร
- หลังลบ `run.bat` / `seed_ah.py --with-history` จะ **ไม่นำข้อมูลเก่ากลับมาอีก** (ต้องใส่ `--force-history` เท่านั้น)
- บรรทัดคำสั่งแทนหน้าเว็บ: `python scripts/purge_requests.py AH --preview` แล้ว `python scripts/purge_requests.py AH --scope legacy --yes --next-dr 1`

ทางเลือกถ้าอยากเก็บข้อมูลเก่าไว้ดูสถิติ: ไม่ต้องลบ ใช้ **ผู้ดูแลระบบ › นำเข้าข้อมูล › ปิดงานเก่าที่ค้าง** ปิดงานเก่าที่ค้าง Try-out/QC ใน Power Apps แทน — Dashboard/งานค้างจะเหลือเฉพาะงานจริง แต่ MTTR/MTBF ย้อนหลังยังใช้ได้

## H. Checklist ก่อนเปิดใช้จริงบน host ฟรี + ย้ายข้อมูลจากเครื่องโรงงาน

1. Deploy ตาม README ข้อ 3 (Render + Supabase/Neon Postgres + Cloudflare R2) — start command มี `--proxy-headers` แล้ว
2. เปิดเว็บผ่านลิงก์ `https://…onrender.com` ครั้งแรก → ระบบจำ BASE_URL เอง (ลิงก์ใน LINE/QR ถูกต้อง) หรือตั้ง ENV `BASE_URL`

## O. ผังผู้อนุมัติแยกตามบริษัท (v1.5)
ผู้ดูแลระบบ › **🧭 ผังผู้อนุมัติ** — แต่ละบริษัทมีผังของตัวเอง
- เพิ่มกฎ: เลือก **ขั้นตอน** (1 Foreman/Engineer · 2 หัวหน้า Die · 3 รับ Try-out · 4 QC) + **Line** (เลือกหลาย Line หรือ "ทุก Line") + **ผู้อนุมัติ** (หลายคนได้) + ติ๊ก **สำรอง** ถ้าเป็นผู้อนุมัติแทน
- ลำดับที่ระบบใช้: กฎของ Line นั้น → กฎ "ทุก Line" → ถ้าไม่มีกฎเลย ใช้บทบาท + Line ประจำของผู้ใช้ (แบบ v1.4) · ปุ่ม ⚡ สร้างผังจากข้อมูลปัจจุบัน ช่วยเริ่มต้น
- ตาราง **Line × ขั้นตอน** แสดงผลลัพธ์จริงที่ระบบใช้ พร้อมเตือน Line ที่ไม่มีผู้อนุมัติ / ผู้อนุมัติที่ไม่มีอีเมล
- ผลที่ได้:
  - ปุ่มอนุมัติแสดงเฉพาะผู้อยู่ในผังของ Line นั้น — คนอื่นกดไม่ได้ (Admin / Manager อนุมัติแทนได้ ประวัติบันทึก "อนุมัติแทน")
  - แท็บ **รอฉันอนุมัติ**, ตัวเลขหน้าหลัก, อีเมล/กระดิ่ง ส่งเฉพาะผู้อนุมัติตามผัง · ผู้อนุมัติสำรองได้รับเฉพาะตอนเตือนงานค้าง
  - หน้าใบงานแสดง **⏳ รอ: ชื่อผู้อนุมัติ** · หน้าโปรไฟล์บอกว่าตนอนุมัติขั้นไหน Line ไหน
  - การมองเห็น: "เฉพาะของตัวเอง" (ค่าเริ่ม) หรือ "ทั้งบริษัท" — แท็บรอฉันอนุมัติเป็นของตัวเองเสมอ

| 💡 แนะนำรอบ PM | วิเคราะห์ประวัติเสีย 12 เดือน แนะนำรอบ = 70% ของ MTBF ติ๊กเลือกแล้วตั้งแผนได้คลิกเดียว |

- **ใบงาน PM**: เปิดแล้วได้ checklist ทันที ช่างกรอกในหน้าใบงาน (ปุ่ม "ที่ยังว่างทั้งหมด = OK") ต้องตอบครบก่อนกด "ซ่อมเสร็จ" (ปิดได้ในตั้งค่า) · พิมพ์ **PM Check Sheet** ได้ · Try-out ของงาน PM ทำโดย Production/Foreman ของ Line (หัวหน้า Die รับงานตัวเองไม่ได้)
- **ปิดใบงาน PM** → ระบบตั้ง PM ล่าสุด, ครั้งถัดไป และนับ Stroke ใหม่ให้อัตโนมัติ
- **เปิดใบงาน PM อัตโนมัติ**: ผู้ดูแลระบบ › ตั้งค่าบริษัท › PM แม่พิมพ์ › "เปิดล่วงหน้า N วัน" — ทุกเช้าระบบเปิดใบงานและแจ้งหัวหน้า Die (กด ▶ รันตอนนี้ ที่หน้า PM ได้)
- หน้าแม่พิมพ์มีกล่อง **แผน PM** (สถานะ, วันถัดไป, แถบ Stroke, แก้แผน, ประวัติเลื่อน/ทำ PM/Stroke)
- Template ข้อมูลตั้งต้น ชีต 8_Dies มีคอลัมน์ PM Interval Strokes และ Stroke Count

## S. ปรับปรุงความปลอดภัย / ความถูกต้อง (v1.6)
- ถ้าไม่ได้ตั้ง ENV `SECRET_KEY` ระบบสร้างกุญแจสุ่มเก็บใน `data/.secret` (เดิมใช้ค่าตายตัว — ปลอม cookie ได้) · บน host ฟรีควรตั้ง ENV
- กู้คืน Backup หลังล้างใบงาน: ประวัติ/รูปของใบงานเก่าจะไม่ไปติดกับใบงานใหม่ที่ใช้เลข id ซ้ำ
- แก้ไขใบงาน / อะไหล่ / จับเวลา ตรวจสิทธิ์ที่ server (ไม่ใช่แค่ซ่อนปุ่ม) · Production ย้าย Line หลัง Foreman อนุมัติแล้วไม่ได้ · ยกเลิกได้เฉพาะของตัวเองก่อนเริ่มซ่อม
- Foreman / QC อนุมัติใบงานที่ตัวเองแจ้งไม่ได้ (Admin/Manager อนุมัติแทนได้) · หัวหน้า Die มอบหมายช่างใหม่ระหว่างซ่อมได้ (ช่างป่วย/ย้ายงาน)
- เปิดใบงานที่ "ยกเลิก" ก่อนซ่อม → กลับไปรอ Foreman (ไม่ไปรอ QC) · ลบปัญหา/สาเหตุที่ถูกใช้แล้ว → เปลี่ยนเป็นไม่ใช้งานแทน
- Export / วิเคราะห์ ใช้สิทธิ์การมองเห็นเดียวกับรายการงาน · ปิดบัญชีทดลองเฉพาะบริษัทตัวเอง · ปิดบริษัทแล้วผู้ใช้บริษัทนั้น login ไม่ได้
